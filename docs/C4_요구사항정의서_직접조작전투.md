## 1. 목적
지도에서 구역을 차지해 나가는 판(C1~C3) 위에 **내가 직접 움직여 싸우는 전투**를 얹는다. 내 조직이 낀 습격 · 방어에서 원하면 참전 간부 하나를 골라 실시간 3D 탑뷰 화면에서 싸우고(동료는 컴퓨터 · 교대), 원하지 않으면 자동 플레이를 보거나 결과만 본다. 직접 싸운 결과는 지금의 틱 자동 전투 · 일기토 카드와 **같은 규칙 · 같은 뒤처리**로 판에 들어간다. **완료 기준은 폰에서 시나리오 A 의 습격 하나를 직접 조작으로 3구간 돌파**다.

## 4. 완료 기준
1. 서버 `python3 -B scripts/verify.py` 종료 코드 0 · CI build 통과 · A 등급(`fight/` 포함) 커버리지 ≥ 90% · B ≥ 70%.
2. headless — 틱만 쓴 26주 해시는 기준값(받기 뒤 새 기준값)과 같다. 구간 결과를 넣은 판은 같은 기록을 다시 돌리면 해시가 같다. v1 저장을 v2 로 옮겨 이어 한다.
3. 같은 규칙 시험이 띠 안(FR-421).
4. 폰 — A 의 습격 하나를 직접 조작으로 3구간 돌파 → 구역 차지 → 보고. 자동 플레이 보기 · 결과만 보기 · 설정 기본값 · 접기/펴기 · 백그라운드 복귀.
5. 성능 — 전투 화면 fps 최저 30 이상(목표 60) · 지도 fps 55 이상((나)40) · APK 예산((나)47).
6. 스크린샷 — xvfb(가로 전투 화면) · CI · 폰 한 장(`docs/screenshots/C4/`).

**C4-0 완료 기준**(이 배치): verify OK(새 단계 '구간 전투' 포함) · `--fight-test` 가 같은 시드에 같은 줄 · CI APK 빌드 · APK 크기 기록 · xvfb 스크린샷. 폰 확인('전투 시험' 한 판 · 방향 전환 · fps)은 rc 태그(사용자 확인) 뒤.

## 5. 위험
- **화면 회전**: 폴드 4 안쪽 화면(약 6:5)에서 가로 요청이 어떻게 보이는지는 폰에서만 안다. 안 되면 방향은 두고 기준 크기만 바꾼다(세로 전투).
- **APK 80 MB**: rc.3 이 75.5 MB — 모델 · 그림 코드로 넘을 수 있다. C4-0 에서 재고 넘으면 묻는다((나)47).
- **에뮬레이터 그림**: castle_M3D 는 CI 에뮬레이터에서 3D 셰이더가 깨졌다(그 판 트러블슈팅 T-2 · T-4). 에뮬레이터 점검은 흐름 · 자가 해시만 보고, 그림은 xvfb · 폰으로 본다.
- **손맛 대 같은 규칙**: castle_M3D 는 사람이 이기게 맞춘 판이다(적은 예고를 보이고 동시에 둘만 친다 · 보스 체력이 크다). 틱과 띠를 맞추면 손맛이 달라질 수 있다 — 봇 실력과 3층 값(`fight.json`)으로 맞추고, 직접 조작은 사람 실력만큼 더 낫게 둔다.
- **막기 0.7**: 2층 값을 쓰면 castle_M3D(0.2)보다 막기가 약하다 — 폰 손맛이 나쁘면 3층으로 내릴지 묻는다.
- **이식 크기**: 판정 2,164줄 + 그림 · 조작 약 3,500줄. A 등급 커버리지 90% 를 지키려면 castle_M3D 시험도 옮겨야 한다.
- **받기**: 92차는 등급을 바꿔 기준 해시가 바뀐다 — 받기 배치에서 한 번에 한다. 공개 판 예외는 사용자 작업(토큰 또는 비공개 전환)이 있어야 끝난다.
