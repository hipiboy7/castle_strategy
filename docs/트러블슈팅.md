## T-1 · CI 에뮬레이터가 부팅하지 않음 — "Timeout waiting for emulator to boot" · 2026-11-10
- **증상**: 수동 실행(emulator=true) run [`42735744915`](https://github.com/hipiboy7/castle_strategy/actions/runs/42735744915)에서 build 단계는 다 통과했다. 그런데 에뮬레이터 단계가 `adb: device 'emulator-5554' not found` 를 900초 동안 되풀이하다 `##[error]Timeout waiting for emulator to boot.` 으로 실패했다(17분).
- **원인**: 에뮬레이터 기동 로그 `FATAL | Not enough space to create userdata partition. Available: 7126.27 MB at /home/runner/.android/avd/test.avd, need 7372.80 MB.` — 잡 하나(artifact 를 넘기지 않으려고 build 와 에뮬레이터를 합쳤다)에서 Godot · 안드로이드 템플릿 · APK · Android 이미지를 다 받은 뒤라 러너 디스크가 약 250MB 모자랐다. castle_M3D 는 잡을 둘로 나눠 새 러너에서 띄워서 이 문제가 없었다.
- **조치**: `.github/workflows/android.yml` 에 '디스크 비우기 (에뮬레이터용)' 단계를 더했다. 에뮬레이터 앞에서 쓰지 않는 도구(dotnet · ghc · boost · node_modules · swift · CodeQL · julia)와 `.godot` · `.tools` 를 지운다.
- **재발 방지**: 잡을 다시 나누지 않는다 — 계정 Artifact 저장 한도가 차 있어 APK 를 잡 사이에 넘길 수 없다. 단계 앞뒤의 `df -h /` 출력으로 남은 공간을 본다.
- **확인**: 다시 돌린 수동 실행 run 의 '디스크 비우기' 출력과 에뮬레이터 단계 결과 — `docs/C1_테스트결과서_시뮬코어.md` 1절.

## T-2 · 폰 GitHub 앱에서 릴리스 APK 를 바로 받지 못함 — "탭 누르기에서 더이상 진행 안됨" · 2026-11-10
- **증상**: 사용자가 폰 GitHub 앱 → 상위 리포지토리 → `castle_strategy` → 릴리스에서 `v0.1.0-rc.2` APK 를 받으려 했는데, 누른 뒤 받기가 진행되지 않았다. 사용자 말: "너 github app > 상위리포지토리 > castle_strategy > 릴리즈 에서 바로 다운로드 되도록 안되어있는데?"
- **원인**: `.github/workflows/android.yml` 이 `-rc` 태그를 `--prerelease` 로 올렸다. 그래서 저장소에 Latest 릴리스가 없었다. castle_M3D 는 사용자 결정(2026-11-05 "프리릴리스로 두지 않는다")대로 `-rc` 도 `--latest` 로 올리고, 폰에서 맨 위 릴리스로 바로 받는다. 워크플로를 옮겨 올 때 이 결정은 옮기지 않았다. 개발 규격 7절은 프리릴리스와 Latest 를 둘 다 허용하고, 판마다 하나로 정하라고 한다. 작업 서버에서는 GitHub 앱의 화면을 재현할 수 없다 — 원인은 castle_M3D 와 다른 점으로 정했다.
- **조치**: `gh release edit v0.1.0-rc.2 --prerelease=false --latest` 로 바꿨다. 본문 맨 위에 바로 받기 링크(`releases/download/v0.1.0-rc.2/castle_strategy-v0.1.0-rc.2.apk`)를 더했다. 확인: `gh release list` → `캐슬 제패 v0.1.0-rc.2	Latest` · 링크 `curl -sIL` → `200 application/vnd.android.package-archive`. 워크플로는 모든 태그를 `--latest` 로 올리고, 본문 맨 위에 같은 꼴의 링크를 쓴다. CLAUDE.md 7절 · `docs/폰확인.md` 설치 1 · 2 · 기획_차이 (다)13 도 고쳤다.
- **재발 방지**: 다른 판의 CI · 배포 설정을 옮길 때는 그 판의 사용자 결정(파일 머리 주석)을 같이 옮긴다. 릴리스를 올린 뒤에는 `gh release list` 에 `Latest` 가 붙었는지 본다.

## T-3 · CI build 가 '문서 명령' 단계에서만 실패 — "없는 것: README.md: .tools/artvenv/" · 2026-11-10
- **증상**: C2 배치 ① push 의 CI run [`42803736320`](https://github.com/hipiboy7/castle_strategy/actions/runs/42803736320)이 43초 만에 실패했다. 서버 verify 는 11/11 이었다. CI 출력: `[FAIL] 문서 명령 — 없는 것: README.md: .tools/artvenv/`.
- **원인**: README 빠른 시작에 도트 받기용 가상환경 폴더를 코드 표기(백틱)로 적었다. '문서 명령' 단계는 백틱 안의 경로가 저장소에 있는지 본다. 그 폴더는 작업 서버에만 있고(`.gitignore` 의 `.tools/`), CI 의 새 체크아웃에는 없다.
- **조치**: README 에는 만드는 명령(띄어쓰기가 있어 경로 검사 대상이 아님)만 적고, 폴더 경로를 코드 표기로 쓰지 않는다. 서버 verify 는 그 폴더가 있어 통과했으므로 CI 결과까지 본 뒤 다음 배치로 간다.
- **재발 방지**: README · 테스트결과서 · 폰확인에 `.tools/` · `.work/` 아래 경로를 코드 표기로 쓰지 않는다(서버에만 있다).

## T-4 · 폰에서 끌어 놓기 · 맡기기 · 주 끝내기가 모두 안 됨 · 닫기도 없음 — v0.3.0-rc.1 · 2026-11-11
- **증상**: 사용자 폰(v0.3.0-rc.1 을 앞 판 위에 덮어 설치)에서 "김신을 끌어 회암시장(D)에 놓아도 아무런 다음 액션이 없음 · 맡기기, 주 끝내기 단추가 눌러도 안됨 · 닫기 버튼도 없음". CI 에뮬레이터(새로 설치 · 저장 없음)는 같은 APK 로 맡기기 → 주 끝내기 → TURN 6 이 됐다.
- **원인(추정 · 서버 재현)**: 앞 판 저장이 이미 26주를 넘긴 판이면 앱이 `over` 단계로 연다. 이 단계는 끌어 놓기를 조용히 버리고 맡기기 · 주 끝내기를 끄며, 나갈 길(기록 탭 → 새 판으로)이 화면 어디에도 안 보였다. 26주 뒤 저장(턴 27)을 `user://` 에 두고 앱을 띄워 같은 처리기를 부르니 세 증상이 그대로 났다. C2 저장(4주)으로는 drop → 고르기 7줄 · 맡기기 6개 · 주 끝내기 → 보고 · 닫기 → play 로 정상이었다.
- **조치**(`ui/app.gd`): `over` 면 아래 '주 끝내기' 자리가 **새 판으로**(켜짐 · 확인 창)가 되고 안내 글이 뜬다. 받지 않은 손 입력(끌어 놓기 · 구역 누름 · 맡기기 · 주 끝내기)은 아래 글에 까닭을 보이고 logcat `INPUT ignored phase=… sheet=…` 를 찍는다. 보고 단계인데 보고가 닫혀 있으면 `play` 로 되돌린다. 기록 탭 정보 줄에 화면 상태(단계 / 창)를 보인다.
- **재발 방지**: 에뮬레이터 점검은 저장 없는 새 설치만 본다 — 폰 확인 목록에 '앞 판 위 덮어 설치'를 늘 두고, 입력을 버리는 곳은 까닭을 화면에 낸다.

## T-5 · SVG 초상에 앞머리 뿌리마다 검은 계단 · 빡빡머리 색이 가운데만 빠짐 — Godot 4.7.2 SVG(ThorVG) · 2026-11-11
- **증상**: `scripts/draw_portraits.py` 2차 그림을 Godot 으로 가져와 보니 앞머리 다발 뿌리 근처에 검은 네모가 계단처럼 나고, 빡빡머리 옅은 색이 얼굴과 겹친 이마에서만 빠졌다. 파이썬 쪽 XML 은 맞았다.
- **원인(층을 하나씩 빼 보며 확인)**: 한 `<clipPath>` 안에 겹치는 `<path>` 여럿을 넣으면 ThorVG 가 그것들을 SVG 규격처럼 '합집합'으로 보지 않고 감는 방향으로 합친다. 감는 방향이 반대인 두 모양이 겹친 곳은 구멍이 되어, 그 안에 그린 채움이 잘리고 밑의 외곽선(검정)이 보였다.
- **조치**: `clip()` 이 path 하나만 받게 바꿨다(여러 개를 넘기면 바로 깨지게). 겹치는 모양(앞머리 덩어리 + 다발들 · 얼굴 + 두피)은 모양마다 따로 자른다 — 덤으로 다발마다 그늘이 따로 진다. 빡빡머리 색은 자르지 않고 두피 안 모양으로만 그린다.
- **재발 방지**: SVG 를 손으로 만들 때 clipPath 는 path 하나. 그림을 바꾸면 Godot 으로 그린 모아 보기(작업 서버 `--headless --script` · `Image.load_svg_from_string`)로 확인한다 — 브라우저 · 다른 그리기 도구 결과를 믿지 않는다.

## T-6 · 보고에 '전투 보기' 단추가 안 보임 · 펼친 화면에서 손가락으로 내리기가 잘 안 됨 — v0.3.0-rc.2 · 2026-11-11
- **증상**: 사용자 폰(갤럭시 Z 폴드 4 · v0.3.0-rc.2) — "김신, 서진태, 피우진 회암 시장에 보내놓고 주 끝내기 하니까 보고의 '전투 보기' 버튼이 없는데? 그냥 전투 1 하고 설명칸만 있음" · "화면을 편 상태에서는 '보고' 등 위아래로 손가락으로 화면 내리기가 잘 안먹혀". 같은 날 "4주 보고에 승리 - 부진파는 잘나온다".
- **원인(두 가지가 겹침)**: ① 전투 카드가 보고 맨 끝이고, '전투 보기' 단추는 그 카드의 설명 줄 아래에 있었다 — 맨 밑까지 내려야 보인다. ② Godot 4.7 의 `PanelContainer` 기본 `mouse_filter` 가 `STOP`(0)이다(작업 서버에서 `PanelContainer.new().mouse_filter` 를 찍어 확인 — `VBoxContainer` 는 PASS 1 · `Label` 은 IGNORE 2). 보고 카드(RowPanel) 위에서 시작한 끌기는 카드가 먹어 `ScrollContainer` 까지 가지 않는다 — 카드 사이 틈과 스크롤 막대에서만 움직였다. 그래서 ① 의 단추까지 내려가기 어려웠다.
- **조치**: `ui/touch_scroll.gd` — `ui/app.gd` 가 `SceneTree.node_added` 에 이어, 스크롤 목록 안에 들어오는 STOP 판을 PASS 로 바꾼다(보고 · 탭 쪽 · 구역 카드 · 고르기 창 모두). 단추는 그대로 STOP(끌다 놓은 자리에서 단추가 눌려 잘못된 명령이 나가지 않게 — 단추 위에서 시작한 끌기는 여전히 스크롤하지 않는다). 보고는 싸움이 있던 주에 **목표 → 전투** 카드를 맨 앞에 두고, 단추를 카드 제목 바로 밑에 두고, 아래 '닫기' 옆에 **전투 보기** 단추를 늘 둔다(`ui/view.gd` `report_cards` · `goal_card` · `ui/report_view.gd`).
- **재발 방지**: 스크롤 목록 안에 판을 새로 넣으면 `ui/touch_scroll.gd` 가 알아서 바꾼다(시험 `tests/unit/test_touch_scroll.gd`). 꼭 눌러야 하는 단추는 스크롤 맨 밑에 두지 않는다. 작업 서버(headless)는 `DisplayServer.is_touchscreen_available()` 이 false 라 손가락 끌기 스크롤을 재현하지 못한다 — 폰에서 본다.
