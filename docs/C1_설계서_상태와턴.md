## 3. 인터페이스

### 3-1. RNG — `sim/rng.gd` (RefCounted · 쓰는 쪽은 `const Pcg32 = preload("res://sim/rng.gd")`)
- **수열**: PCG32 `pcg32_random_r` 과 같다.
  - 상태 64비트 · 증분 64비트 · 곱수 `6364136223846793005`(`0x5851F42D_4C957F2D`).
  - 출력: `xorshifted = ((old >> 18) ^ old) >> 27` · `rot = old >> 59` · `rotr32(xorshifted, rot)`.
  - 씨앗(`pcg32_srandom_r`): `state = 0` · `inc = (initseq << 1) | 1` · 한 번 돌림 · `state += initstate` · 한 번 돌림.
- **64비트 표현**: 32비트 두 쪽(`hi` · `lo`, 둘 다 0 ≤ x < 2³²)으로 둔다. 곱은 16비트 조각 곱으로 하고, 모든 중간값은 2³⁴ 아래다 — GDScript int64 넘침에 기대지 않는다.
- **API**(인스턴스 — 자기를 돌려줘 이어 쓴다: `Pcg32.new().init_stream(…)`):
  - `func seed_with(state_hi, state_lo, seq_hi, seq_lo) -> RefCounted`
  - `func init_stream(seed: int, turn: int, phase: String, target: String) -> RefCounted` — SHA-256(UTF-8 `"%d|%d|%s|%s"`) 앞 16바이트 = initstate(0~7) · initseq(8~15), 빅엔디언.
  - `func next_u32() -> int`(0 ≤ x < 2³²) · `func below(n: int) -> int`(`pcg32_boundedrand_r` 거절법 — 편향 없음) · `func chance_bp(bp: int) -> bool`(만분율 확률 — `below(10000) < bp`).
- **시험 기대값**: `tools/rng_ref.py`(Python 정수 — 기준 구현)가 만든다. 공개 데모 수열(`pcg32_srandom_r(42, 54)` → `0xa15c02b7 0x7b47f409 0xba1d3330 …`)과 먼저 맞춘다.

### 3-2. 해시 — `sim/hash.gd` (쓰는 쪽은 `const StateHash = preload("res://sim/hash.gd")`)
- `static func canonical(v) -> String` — 정규형 JSON 이다.
  - dict 는 키(String 만)를 코드 포인트 순으로 정렬하고, 배열은 순서를 그대로 둔다.
  - 정수는 10진, `true` · `false` · `null` 은 그대로 쓴다.
  - 문자열은 `"` `\` 와 제어 문자(U+0000~001F)만 `\"` `\\` `\n` `\r` `\t` `\u00XX` 로 바꾼다.
  - 공백이 없다. **실수(float)나 String 이 아닌 키가 있으면 빈 문자열을 돌려준다**(상태는 정수만). 까닭은 `check(v)` 가 돌려준다 — `sim/` 은 출력하지 않는다(부른 쪽이 정한다 · verify 는 출력의 `ERROR:` 를 실패로 본다).
- `static func of(v) -> String` — `canonical(v)` 의 SHA-256 앞 16자(소문자 16진).
- 상태 해시는 `of(state.to_dict())` 다. 화면용 `TurnReport` · 로그는 해시에 넣지 않는다.

### 3-3. GameState v1 — `sim/state.gd`
- **꼴**: 상태는 정수 · 문자열 · bool · 배열 · 사전만 든 **사전**이다(객체 아님 — 해시 · 저장이 그대로 된다). `sim/state.gd` 는 static 함수만 둔다: `new_state` · `new_org` · `new_officer` · `new_zone`(기본값) · `to_dict`(깊은 복사) · `from_dict`(JSON 실수 → 정수 · 칸 검사 → `{state, errors}`) · `hash_of` · `check_invariants(s, t)` · `officers_of(s, org, active_only)`.
- 빈 값은 `""` 로 둔다(`vassal_of` · `elite.unit` · `boss` · `hq` — null 을 쓰지 않는다). 빈 사업장 칸은 `org: ""` · `lv: 0` 이다.
- **단위**:
  - 돈 · 머릿수 · 체력은 정수다.
  - 백분율(열기 · 충성 · 결속 · 사기 · 경찰 압력 · 유동)은 **×100 정수**다(0~10000 = 0.00~100.00%, 유동은 10000 = 1.00배).
  - 지분 · 상납률은 **만분율**이다(지분 합 10000 = 100%, 상납 1500 = 15%).
  - 등급은 `data/ranks.json` `ladder` **이름**으로 둔다(08 12절). 번호는 표에서 그때 계산한다.
- **최상위**: `v`(1) · `seed` · `scenario` · `mode`(`canon` | `if`) · `length`(26 · 52 · 0 = 끝없음) · `turn`(다음에 처리할 턴 · 1부터) · `player`(조직 id) · `orgs` · `officers` · `zones` · `castle` · `events_done`(팩 사건 id · 일어난 순) · `progress_done`(진행 사건 id `beat:` 등 — 기획_차이 (가)) · `flags`.
- **orgs[id]**:
  - 기본: `cash` · `heat` · `fame` · `cohesion` · `boss` · `hq` · `alive`
  - 조직원 · 정예: `troops`(`{"건달급": n, "조장급": n, "네임드": n, "경호대급": n}`) · `elite`(`{"unit": 단위 id 또는 "", "n": 0}`)
  - 외교 · 상납 · 빚 · 정보: `relations`(`{조직 id: {"state": "neutral"|"truce"|"alliance"|"war", "until": 턴}}`) · `vassal_of` · `tribute_bp` · `debts`(`[{"to", "amount", "due"}]`) · `intel`(`{구역 id: 0~3}`)
  - 턴 기록: `neg_cash_turns` · `hq_lost_turn`(−1)
- **officers[인물 id]**:
  - 소속 · 자리: `org` · `zone` · `post`(`boss` · `staff` · `zone_chief` · `captain` · `guard` · `""`)
  - 등급: `rank` · `rank_prov`(자리값이면 true)
  - 상태: `loyalty` · `wound` · `status`(`active` · `wounded` · `captive` · `dead` · `away`)
  - 기술: `skills` · `seen`(`{기술 id: 본 횟수}`) · `mastery`
- **zones[구역 id]**:
  - `owner`(조직 id 또는 "") · `flow` · `people` · `police`
  - `slots`(`[{"kind": 업종, "org": 조직 id 또는 "", "lv": 1~3, "dmg": 0}]`) · `facilities`(`office` · `warehouse` · `dojo` · `clinic` · `hq`)
- **castle**: `chair` · `stakes`(`{조직 id: 만분율}`) · `next_council` · `enemies`.
- **불변식**(`check_invariants(tables) -> Array[String]` · 매 턴 · 비면 통과):
  - 머릿수 ≥ 0. 백분율 · 만분율은 범위 안이다.
  - `stakes` 가 비어 있지 않으면 합이 10000 이다.
  - `dead` 인 간부의 명령은 없다. 구역 `owner` 는 "" 이거나 살아 있는 조직이다.
  - 모든 id 가 표에 있다.
  - 돈은 음수를 허용한다(08 3-1 '0 밑으로 2턴'). 08 16절의 '돈 음수 없음'과 갈리는 곳이다 — 7절.

### 3-4. 명령 — `sim/orders.gd`
- 꼴: `{"org": 조직 id, "by": 인물 id, "kind": 명령 종류, "to": 구역 id 또는 "", "args": {...}, "src": "player"|"ai"}`.
- **검사**:
  - 간부가 그 조직의 `active` 여야 한다.
  - 행동 수는 간부 1, 두목 2 다(08 2절 · `data/game/game.json`).
  - 종류가 등록부에 있어야 하고, 대상이 올바라야 한다.
  - 틀린 명령은 적용하지 않고, 까닭을 `TurnReport` 에 남긴다(결정적).
- **등록부**(OCP): `KINDS = {종류: {"phase": 단계, "mod": preload("res://sim/kinds/<종류>.gd")}}`. C1 의 종류는 `move` · `open`(개업) · `expand`(확장) · `recruit`(모집) · `rest` 다. 새 종류는 처리기 파일 하나 + 표에 한 줄이다.
- **처리기 꼴**(LSP): `static func apply(s, o, ctx) -> String` — 검사와 적용을 같이 하고, 거절이면 까닭을 돌려준다("" = 적용). 마감(plan) 때는 꼴 · 조직 · 간부(active · 소속) · 종류 · 행동 수만 보고, 나머지는 적용 때 본다(앞 명령이 돈 · 칸 · 자리를 바꿨을 수 있다). 거절된 명령은 행동 수를 쓰지 않는다.
- **C1 처리기**:
  - `move`: 땅길 이웃(`data/game/map.json` links)으로만.
  - `open`: 간부가 있는 구역 · 자기 구역이나 주인 없는 구역의 첫 빈칸 → lv1 · 비용 BASE × `open_cost_k`.
  - `expand`: 간부가 있는 구역의 자기 칸(`args.slot` 또는 가장 낮은 레벨) +1(최대 3) · 비용 BASE × `expand_cost_k` × 오를 레벨.
  - `recruit`: 자기 구역 · 건달급 = 사람 × `per_people` + 난수(0 ~ `rand`−1 · 스트림 대상 = 간부 id) · 돈만큼만 · 머릿수 × `cost`.
  - `rest`: 바꾸지 않는다(부상 회복은 C3).
  - 쓰는 돈으로 현금이 음수가 되지 않는다(모자라면 거절). 음수는 결산의 유지비로만 생긴다.
- **AI**(`sim/ai.gd` — C1 은 경영만 · 결정적): 조직마다 사본 상태에 처리기를 미리 적용하며 간부(id 순) × 행동 수만큼 고른다 — ① 지금 구역 개업 ② 확장 ③ 모집(조직원 < 사업장 × 5 · 주 순이익 ≥ 새 유지비 × 2) ④ 이동(한 턴 한 번 · 구역장은 떠나지 않음 · 아무도 노리지 않은 빈칸이 있고 열 돈이 있는 이웃 → 없으면 자기 사업장이 없는 곳에서 자기 사업장 이웃(본거지 먼저)으로) ⑤ 쉼. 돈은 쓰고 나서도 2주 적자를 버틸 만큼(최소 20) 남긴다. 판 밖 조직(간부 away)은 명령이 없다.
- **처리 순서**: 조직 id 오름차순 → 간부 id 오름차순 → 한 간부 안에서는 낸 순서(08 13절 1).

### 3-5. 턴 — `sim/turn.gd`
- `static func run(state, orders, t) -> {"state": 새 상태, "report": 보고}` — 입력 상태는 바꾸지 않는다(깊은 복사 뒤 처리). 보고 = `{turn, applied, rejected[{order, why}], events, money{조직: {income, upkeep, cash}}, invariants}`.
- 등록부 `HANDLERS = {단계: {"mod": 모듈, "fn": 함수 이름}}` — plan · move · manage 는 `sim/orders.gd`, settle 은 `sim/economy.gd`.
- 단계(08 13절) `PHASES = ["plan", "move", "manage", "intrigue", "diplomacy", "clash", "events", "council", "settle"]`.
  - 처리기가 없는 단계는 건너뛴다.
  - C1 처리기는 `plan`(명령 마감 · 정렬) · `move` · `manage`(개업 · 확장 · 모집) · `settle`(수입 → 지출 → 현금 규칙 → 불변식 → `turn += 1`) 이다.
- 단계 처리기 꼴(LSP): `<모듈>.<함수>(s, ctx) -> void`.
  - `ctx` = `{t, seed, turn, phase, all(이번 턴 명령 전부), accepted(단계별 받은 명령), report}`. 난수는 처리기가 `Pcg32.new().init_stream(seed, turn, phase, 대상 id)` 로 만든다.
  - 한 단계 안에서도 대상마다 스트림이 따로라, 명령 하나가 바뀌어도 다른 대상의 난수는 밀리지 않는다.

### 3-6. 정수화 규칙 — `sim/fixed.gd`
- 나눗셈은 0 이상이면 **반올림**(`(a + d / 2) / d`)이고, 음수는 0 쪽 대칭이다. 한 공식은 한 번만 나눈다(분자를 다 곱한 뒤 — 중간값은 int64 안).
- castle_common 규칙 함수의 실수 결과(`rank_damage_k` 등)는 받자마자 `k_milli = int(round(k × 1000))` 로 바꿔 쓴다. 덧셈 · 곱셈 · 나눗셈만 쓰는 함수라 IEEE 결과가 플랫폼마다 같다. 거듭제곱 · 삼각 함수는 쓰지 않는다.
- **14-1 수입(정수판)**:
  - 공식: `round(BASE[업종] × lv × flow × (800 + 4 × 수완) × (20000 − heat) × match ÷ (10000 × 1000 × 20000 × 1000))`.
  - 인자: `flow` 는 10000 = 1.00배, `heat` 는 ×100(0~10000), `match` 는 돈줄이 맞으면 1250 · 아니면 1000 이다.
  - 수완은 구역장의 `business`(없으면 0) — 08 의 `(0.8 + 수완/250)` × 1000 과 같다.
  - `(20000 − heat) ÷ 20000` 은 08 의 `(1 − 0.5 × 열기/100)` 이다.
  - 가장 큰 중간값(물류 80 × lv 3 × 유동 2.0배 × 수완 100 × 열기 0 × 1250)은 약 1.4 × 10¹⁷ 로 int64 안이다.
  - 값(BASE · 유지비 · 대우 · 현금 규칙)의 원천은 `data/game/economy.json` 이다. 시작값은 08 14-1 이다. 식의 상수도 그 파일에 둔다: `biz_base_milli` 800 · `biz_per_point_milli` 4 · `heat_div` 20000(= 08 의 0.5) · `match_milli` 1250. 칸마다 반올림해 더한다.
- **구역장**: 그 구역에 있는 그 조직의 active 간부 중 수완이 가장 높은 사람(자리 `zone_chief` 를 따로 두지 않는다 — 간부 배치가 곧 구역장). 없으면 수완 0.
- **유지비**: 조직원 등급별 × 머릿수 + 간부 대우(등급 번호 × 3) — 대우는 `active` · `wounded` 간부만(포로 · 판 밖 · 죽음은 없음).
- **현금 규칙**(08 3-1): 결산 뒤 현금 < 0 이면 `neg_cash_turns` +1(0 이상이면 0). 2턴 이상이면 그 턴마다 등급별 10% 올림이 떠나고 간부 충성 −500(0 밑으로 안 감) · 보고 `events` 에 `leave`.

### 3-7. 저장 v1 — `sim/save.gd`
```json
{"format": "castle_strategy.save", "format_version": 1, "game_version": "0.1.0",
 "castle_common": "<받은 sha>", "seed": 12345, "scenario": "A", "player": "bujinpa", "mode": "canon",
 "turn": 7, "state": {"…GameState v1…": 0}, "orders": [{"turn": 1, "orders": ["…명령 꼴…"]}]}
```
- `orders` 는 플레이어와 AI 의 명령을 다 담는다(`src`). 다시 돌리기 방식은 둘이다:
  - **같은 명령**: 시뮬만 바뀌었는지 본다.
  - **AI 다시 계산**: AI 가 바뀌었는지 본다.
- **불러오기**(`Save.from_text(text, t) -> {save, errors, notes}`):
  - 깨진 글 · 다른 `format` 은 오류다. JSON 수(실수)는 정수로 되돌린다(정수 꼴이 아니면 오류).
  - `format_version` 이 낮으면 옮김 함수를 차례로 적용한다(`MIGRATE[v]`). **v0** = C1-0 빈 시뮬 저장(`{v, seed, turn, acc, last}` · `format` 없음) → 같은 시드 · 시나리오 A · 빈 상태 · 명령 없음(= 새 판).
  - 그다음 canon `replaced_by`(인물 · 조직 · 장소)로 id 를 옮긴다 — 상태의 키(orgs · officers · zones)와 참조(boss · hq · vassal_of · org · zone · owner · 칸 org · player), 명령 기록(org · by · to), 저장의 player. 옮긴 id 는 `notes` 에 남긴다.
  - 더 높은 판이면 거절한다. 파일은 sim 이 건드리지 않는다 — 화면(C1 ui/home.gd · C2 `ui/app.gd`)은 읽지 못한 저장을 `user://save_auto.broken.json` 으로 옮겨 두고(지우지 않음) 새 판으로 연다.
- **이어 하기**(`Game.from_save`): 상태가 있으면 그대로(불변식 검사), 비었으면 명령 기록을 처음 상태에서 다시 돌려 만든다(같은 명령).
- **자동 저장**: 턴마다 · 백그라운드로 갈 때. `user://save_auto.json` 에 쓴다(쓰기 → 같은 폴더 임시 파일 → 이름 바꾸기).

### 3-8. 규칙 함수 · 정적 표 — `sim/rules_common.gd` · `sim/tables.gd` · `src/data_files.gd`
- `src/data_files.gd` `read(paths)` 가 `res://data/` 아래 상대 경로(`common/ranks.json` …) 목록을 읽어 `{files, errors}` 를 낸다. `sim/` 은 그 `files` 사전만 받는다.
- `RulesCommon.from_files(files)` — 받은 사본 5개(`FILES`)로 만든 인스턴스. 함수 20개는 `ref/rules.py` 와 같은 이름 · 인자다(인스턴스 메서드). 모르는 등급은 −1 이고 찍지 않는다.
- `Tables.build(files)` → 읽기 전용 사전: `ranks` · `rank_no` · `below` · `rules`(RulesCommon) · `chars`(전투 능력치) · `people`(canon 인물 id) · `replaced`(canon 인물 · 조직 · 장소 `replaced_by`) · `trades` · `factions` · `units` · `districts` · `scenarios` · `strat`(전략 능력치 — 정수) · `tags` · `errors`. 읽을 파일 목록은 `Tables.NEEDS` 다.
- 함수: `current_id(t, id)`(replaced_by 끝까지) · `resolve(t, id, 시나리오)`(factions.json `resolve` — becomes → parent → null = 무소속 "") · `hq_of(t, org, 시나리오)` · `districts_in(t, 시나리오)`(owners 에 키가 있는 구역 · id 순).
- id 검사(오류 `파일:id — 까닭`): 명단 인물(canon) · 소속 · 등급(사다리 · `below` · null) · 배치 · 고를 수 있는 조직 · 구역 주인 · 업종 · 본거지 · 두목 · 대표 간부 · 정예 단위 · becomes · 단위 부모 · 전략 능력치 인물 · replaced_by 고리. 팩이 비워 둔 값(null — 업종 · 정예 단위 · 본거지)은 허용한다.

### 3-9. 시나리오 처음 상태 — `sim/setup.gd`
- 판 조직 = 명단 소속(assign 이 덮음)과 이 시나리오 구역 주인을 `resolve` 한 조직. 정치 · 공권력(`units` kind `state`)은 무소속으로 풀려 빠진다.
- 본거지(`hq_of`)가 이 판 구역에 없으면 **판 밖 조직**: `hq` "" · 조직원 0 · 그 간부는 `away`(행동 · 대우 없음 — A 의 이스크라 · 하성). 무소속 간부도 `away` · 구역 "".
- 두목: assign 의 `post: boss` → 팩 두목(그 조직 간부일 때) → 가장 높은 등급. 등급 빈칸은 7절. 충성 = 의리 × 100(없으면 5000). 기술 = `rules_common.progress(id)` 처음 값.
- 값: `data/game/setup.json` 기본값 위에 시나리오 값을 덮는다(조직원은 등급마다). 구역 칸 수만큼 업종을 `trades` 에서 돌아가며 두고, 주인이 앞 `owned_slots` 칸을 lv1 로 쥔다. 본거지 구역 거점은 `hq` · `office`, 다른 자기 구역은 `office`.

## 5. 오류 처리
- **받은 데이터 · 표**: 없는 파일 · 없는 id 는 `errors[]` 에 `파일:id — 까닭` 을 남긴다. verify 는 그 수가 0 이 아니면 실패다. 실행 중에는 개발 빌드면 오류 화면, 배포 빌드면 그 개체를 빼고 로그에 남긴다.
- **명령**: 틀린 명령은 적용하지 않고 `TurnReport` 에 까닭을 적는다(같은 입력 → 같은 거절).
- **저장**: 깨짐 · 더 새 판이면 오류 화면을 띄우고, 원본 파일은 그대로 둔다(덮어쓰지 않음).
- **결정성**: 상태에 실수가 들어가면 `StateHash.canonical` 이 오류를 낸다. 시험에서 잡힌다.
- **지우는 일**: sync 가 `data/common/*.json` 을 지운다. 이 판의 파일은 `data/game/` 에만 둔다.
