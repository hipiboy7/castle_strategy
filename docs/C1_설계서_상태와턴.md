## 3. 인터페이스

### 3-1. RNG — `sim/rng.gd` (class_name `Pcg32`, RefCounted)
- **수열**: PCG32 `pcg32_random_r` 과 같다.
  - 상태 64비트 · 증분 64비트 · 곱수 `6364136223846793005`(`0x5851F42D_4C957F2D`).
  - 출력: `xorshifted = ((old >> 18) ^ old) >> 27` · `rot = old >> 59` · `rotr32(xorshifted, rot)`.
  - 씨앗(`pcg32_srandom_r`): `state = 0` · `inc = (initseq << 1) | 1` · 한 번 돌림 · `state += initstate` · 한 번 돌림.
- **64비트 표현**: 32비트 두 쪽(`hi` · `lo`, 둘 다 0 ≤ x < 2³²)으로 둔다. 곱은 16비트 조각 곱으로 하고, 모든 중간값은 2³⁴ 아래다 — GDScript int64 넘침에 기대지 않는다.
- **API**:
  - `static func seeded(initstate_hi, initstate_lo, initseq_hi, initseq_lo) -> Pcg32`
  - `static func stream(seed: int, turn: int, phase: String, target: String) -> Pcg32` — SHA-256(UTF-8 `"%d|%d|%s|%s"`) 앞 16바이트 = initstate(0~7) · initseq(8~15), 빅엔디언.
  - `func next_u32() -> int`(0 ≤ x < 2³²) · `func below(n: int) -> int`(`pcg32_boundedrand_r` 거절법 — 편향 없음) · `func chance_bp(bp: int) -> bool`(만분율 확률 — `below(10000) < bp`).
- **시험 기대값**: `tools/rng_ref.py`(Python 정수 — 기준 구현)가 만든다. 공개 데모 수열(`pcg32_srandom_r(42, 54)` → `0xa15c02b7 0x7b47f409 0xba1d3330 …`)과 먼저 맞춘다.

### 3-2. 해시 — `sim/hash.gd` (class_name `StateHash`)
- `static func canonical(v) -> String` — 정규형 JSON 이다.
  - dict 는 키(String 만)를 코드 포인트 순으로 정렬하고, 배열은 순서를 그대로 둔다.
  - 정수는 10진, `true` · `false` · `null` 은 그대로 쓴다.
  - 문자열은 `"` `\` 와 제어 문자(U+0000~001F)만 `\"` `\\` `\n` `\r` `\t` `\u00XX` 로 바꾼다.
  - 공백이 없다. **실수(float)나 String 이 아닌 키가 있으면 `push_error` 를 하고 빈 문자열을 돌려준다**(상태는 정수만).
- `static func of(v) -> String` — `canonical(v)` 의 SHA-256 앞 16자(소문자 16진).
- 상태 해시는 `of(state.to_dict())` 다. 화면용 `TurnReport` · 로그는 해시에 넣지 않는다.

### 3-3. GameState v1 — `sim/state.gd`
- **단위**:
  - 돈 · 머릿수 · 체력은 정수다.
  - 백분율(열기 · 충성 · 결속 · 사기 · 경찰 압력 · 유동)은 **×100 정수**다(0~10000 = 0.00~100.00%, 유동은 10000 = 1.00배).
  - 지분 · 상납률은 **만분율**이다(지분 합 10000 = 100%, 상납 1500 = 15%).
  - 등급은 `data/ranks.json` `ladder` **이름**으로 둔다(08 12절). 번호는 표에서 그때 계산한다.
- **최상위**: `v`(1) · `seed` · `scenario` · `mode`(`canon` | `if`) · `length`(26 · 52 · 0 = 끝없음) · `turn`(다음에 처리할 턴 · 1부터) · `player`(조직 id) · `orgs` · `officers` · `zones` · `castle` · `events_done`(팩 사건 id · 일어난 순) · `progress_done`(진행 사건 id `beat:` 등 — 기획_차이 (가)) · `flags`.
- **orgs[id]**:
  - 기본: `cash` · `heat` · `fame` · `cohesion` · `boss` · `hq` · `alive`
  - 조직원 · 정예: `troops`(`{"건달급": n, "조장급": n, "네임드": n, "경호대급": n}`) · `elite`(`{"unit": 단위 id 또는 "", "n": 0}`)
  - 외교 · 상납 · 빚 · 정보: `relations`(`{조직 id: {"state": "neutral"|"truce"|"alliance"|"war", "until": 턴}}`) · `vassal_of` · `tribute_bp` · `debts`(`[{"to", "amount", "due"}]`) · `intel`(`{구역 id: 0~3}`)
  - 턴 기록: `neg_cash_turns` · `hq_lost_turn`(−1)
- **officers[인물 id]**:
  - 소속 · 자리: `org` · `zone` · `post`(`boss` · `staff` · `zone_chief` · `captain` · `guard` · `""`)
  - 등급: `rank` · `rank_prov`(자리값이면 true)
  - 상태: `loyalty` · `wound` · `status`(`active` · `wounded` · `captive` · `dead` · `away`)
  - 기술: `skills` · `seen`(`{기술 id: 본 횟수}`) · `mastery`
- **zones[구역 id]**:
  - `owner`(조직 id 또는 "") · `flow` · `people` · `police`
  - `slots`(`[{"kind": 업종, "org": 조직 id 또는 "", "lv": 1~3, "dmg": 0}]`) · `facilities`(`office` · `warehouse` · `dojo` · `clinic` · `hq`)
- **castle**: `chair` · `stakes`(`{조직 id: 만분율}`) · `next_council` · `enemies`.
- **불변식**(`check_invariants(tables) -> Array[String]` · 매 턴 · 비면 통과):
  - 머릿수 ≥ 0. 백분율 · 만분율은 범위 안이다.
  - `stakes` 가 비어 있지 않으면 합이 10000 이다.
  - `dead` 인 간부의 명령은 없다. 구역 `owner` 는 "" 이거나 살아 있는 조직이다.
  - 모든 id 가 표에 있다.
  - 돈은 음수를 허용한다(08 3-1 '0 밑으로 2턴'). 08 16절의 '돈 음수 없음'과 갈리는 곳이다 — 7절.

### 3-4. 명령 — `sim/orders.gd`
- 꼴: `{"org": 조직 id, "by": 인물 id, "kind": 명령 종류, "to": 구역 id 또는 "", "args": {...}, "src": "player"|"ai"}`.
- **검사**:
  - 간부가 그 조직의 `active` 여야 한다.
  - 행동 수는 간부 1, 두목 2 다(08 2절 · `data/game/game.json`).
  - 종류가 등록부에 있어야 하고, 대상이 올바라야 한다.
  - 틀린 명령은 적용하지 않고, 까닭을 `TurnReport` 에 남긴다(결정적).
- **등록부**(OCP): `KINDS = {종류: {"phase": 단계, "handler": Callable}}`. C1 의 종류는 `move` · `open`(개업) · `expand`(확장) · `recruit`(모집) · `rest` 다. 새 종류는 표에 줄을 더해 늘린다.
- **처리 순서**: 조직 id 오름차순 → 간부 id 오름차순 → 한 간부 안에서는 낸 순서(08 13절 1).

### 3-5. 턴 — `sim/turn.gd`
- `static func run(state: GameState, orders: Array, tables) -> TurnReport`
- 단계(08 13절) `PHASES = ["plan", "move", "manage", "intrigue", "diplomacy", "clash", "events", "council", "settle"]`.
  - 처리기가 없는 단계는 건너뛴다.
  - C1 처리기는 `plan`(명령 마감 · 정렬) · `move` · `manage`(개업 · 확장 · 모집) · `settle`(수입 → 지출 → 현금 규칙 → 불변식 → `turn += 1`) 이다.
- 처리기 꼴(LSP): `static func run(state, ctx) -> void`.
  - `ctx` = `{tables, orders(그 단계 것), rng: func(target) -> Pcg32.stream(seed, turn, phase, target), report}`.
  - 한 단계 안에서도 대상마다 스트림이 따로라, 명령 하나가 바뀌어도 다른 대상의 난수는 밀리지 않는다.

### 3-6. 정수화 규칙 — `sim/fixed.gd`
- 나눗셈은 0 이상이면 **반올림**(`(a + d / 2) / d`)이고, 음수는 0 쪽 대칭이다. 한 공식은 한 번만 나눈다(분자를 다 곱한 뒤 — 중간값은 int64 안).
- castle_common 규칙 함수의 실수 결과(`rank_damage_k` 등)는 받자마자 `k_milli = int(round(k × 1000))` 로 바꿔 쓴다. 덧셈 · 곱셈 · 나눗셈만 쓰는 함수라 IEEE 결과가 플랫폼마다 같다. 거듭제곱 · 삼각 함수는 쓰지 않는다.
- **14-1 수입(정수판)**:
  - 공식: `round(BASE[업종] × lv × flow × (800 + 4 × 수완) × (20000 − heat) × match ÷ (10000 × 1000 × 20000 × 1000))`.
  - 인자: `flow` 는 10000 = 1.00배, `heat` 는 ×100(0~10000), `match` 는 돈줄이 맞으면 1250 · 아니면 1000 이다.
  - 수완은 구역장의 `business`(없으면 0) — 08 의 `(0.8 + 수완/250)` × 1000 과 같다.
  - `(20000 − heat) ÷ 20000` 은 08 의 `(1 − 0.5 × 열기/100)` 이다.
  - 가장 큰 중간값(물류 80 × lv 3 × 유동 2.0배 × 수완 100 × 열기 0 × 1250)은 약 1.4 × 10¹⁷ 로 int64 안이다.
  - 값(BASE · 유지비 · 대우 · 현금 규칙)의 원천은 `data/game/economy.json` 이다. 시작값은 08 14-1 이다.

### 3-7. 저장 v1 — `sim/save.gd`
```json
{"format": "castle_strategy.save", "format_version": 1, "game_version": "0.1.0",
 "castle_common": "<받은 sha>", "seed": 12345, "scenario": "A", "player": "bujinpa", "mode": "canon",
 "turn": 7, "state": {"…GameState v1…": 0}, "orders": [{"turn": 1, "orders": ["…명령 꼴…"]}]}
```
- `orders` 는 플레이어와 AI 의 명령을 다 담는다(`src`). 다시 돌리기 방식은 둘이다:
  - **같은 명령**: 시뮬만 바뀌었는지 본다.
  - **AI 다시 계산**: AI 가 바뀌었는지 본다.
- **불러오기**:
  - `format_version` 이 낮으면 옮김 함수를 차례로 적용한다(`MIGRATE[v]`).
  - 그다음 표의 `replaced_by` 로 id 를 옮긴다.
  - 더 높은 판이면 거절하고 파일은 지우지 않는다.
- **자동 저장**: 턴마다 · 백그라운드로 갈 때. `user://save_auto.json` 에 쓴다(쓰기 → 같은 폴더 임시 파일 → 이름 바꾸기).

## 5. 오류 처리
- **받은 데이터 · 표**: 없는 파일 · 없는 id 는 `errors[]` 에 `파일:id — 까닭` 을 남긴다. verify 는 그 수가 0 이 아니면 실패다. 실행 중에는 개발 빌드면 오류 화면, 배포 빌드면 그 개체를 빼고 로그에 남긴다.
- **명령**: 틀린 명령은 적용하지 않고 `TurnReport` 에 까닭을 적는다(같은 입력 → 같은 거절).
- **저장**: 깨짐 · 더 새 판이면 오류 화면을 띄우고, 원본 파일은 그대로 둔다(덮어쓰지 않음).
- **결정성**: 상태에 실수가 들어가면 `StateHash.canonical` 이 오류를 낸다. 시험에서 잡힌다.
- **지우는 일**: sync 가 `data/common/*.json` 을 지운다. 이 판의 파일은 `data/game/` 에만 둔다.
