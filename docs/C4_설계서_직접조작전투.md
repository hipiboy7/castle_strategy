## 2. 구간 계약
### 2-1. 유닛 — 지금 틱 습격의 꼴 그대로(`sim/combat.gd` `officer_unit` · `group_unit`)
- 간부 `{"t": "o", "id", "side"(0 들어가는 쪽 · 1 지키는 쪽), "rank", "r", "hp", "max", "atk", "imm", "immune", "pin", "down", "wound"}`
- 조직원 묶음 `{"t": "g", "grade", "r", "side", "n", "n0", "dmg", "hp1", "atk1"}`
- 들어가는 쪽 유닛은 구간을 넘어 이어진다(체력 · 머릿수). 지키는 쪽은 구간마다 따로다.

### 2-2. `need` — 실시간으로 풀 구간 하나의 준비(전부 값 사본 · 정수 · 글)
```
{"key": "<구역>|<들어가는 조직>", "turn": 3, "zone": "bukgu", "att": "bujinpa", "def": "dssecurity",
 "i": 0,                      # 구간 번호(0 입구 · 1 안 · 2 본진)
 "side": 0,                   # 묻는 조직이 선 쪽
 "A": [유닛…], "D": [유닛…],   # 이 구간에 선 유닛(2-1)
 "cards": ["charge"], "def_cards": [],
 "known": {"kimshin": {"skills": [...], "seen": {...}}},   # 간부가 아는 기술 · 본 횟수(상태 사본)
 "seed": 2893017345}          # Pcg32.init_stream(seed, turn, "fight", key + "|" + i) 의 첫 값
```
- `need` 를 내는 때: `opts.ask` 가 들어가는 조직이거나 지키는 조직이고, 묶음 키가 `opts.auto` 에 없고, **그 쪽에 서 있는 간부가 이 구간에 하나라도 있고**, `opts.fights` 에 이 구간의 결과가 없을 때. 그 밖에는 틱으로 푼다.

### 2-3. 구간 결과 — 화면이 돌려주는 값(정수 · 글 · 참거짓만)
```
{"v": 1, "i": 0, "by": "direct" | "auto",
 "result": "att" | "def", "ticks": 7,            # 걸린 프레임 ÷ (틱 길이 × 60) 올림 · tick_cap 까지
 "a": [{"t": "o", "id": "kimshin", "hp": 412, "down": false, "wound": 0}, {"t": "g", "grade": "건달급", "n": 5}],
 "d": [{"t": "g", "grade": "건달급", "n": 0}],     # need 의 A · D 와 같은 차례 · 같은 종류
 "morale": [100, 0],
 "seen": {"kimshin": {"offbeat": 1}},             # 이 구간에서 더 본 횟수(더하기 값)
 "frames": 1240, "kills": [9, 0]}                 # 보고용
```
### 2-4. 검증(`sim/combat.gd` `outcome_error(need 의 유닛, 결과) -> 글`) — 틀리면 그 구간은 틱으로 풀고 보고 `rejected` 에 남긴다
- 꼴: `v` · `i` · `result` · `a` · `d` 가 있고, 줄 수 · 차례 · 종류 · `id` · `grade` 가 유닛과 같다.
- 범위: 간부 `0 ≤ hp ≤ 들어올 때 hp`(전투 중 회복 없음) · `down` 이면 `hp = 0` · `0 ≤ wound ≤ PCT_MAX` · 묶음 `0 ≤ n ≤ 들어올 때 n` · `0 ≤ ticks ≤ tick_cap` · 사기 `0 ~ start + duel_win × 간부 수`.
- 승패 일치: `att` 는 지키는 쪽 머릿수 0 이거나 그 쪽 사기 0 일 때만. 그 밖은 `def`.
- `seen` 은 그 구간에 선 `can_copy` 간부 · 이 판에 있는 기술 id 만. 배우기(`copy.seen` · `can_learn`)는 sim 이 판단한다(결과가 정하지 않는다).

### 2-5. 적용 — 한 곳(틱과 같은 길)
- 구간 결과를 유닛에 옮긴다(체력 · 쓰러짐 · 부상 · 머릿수) → 구간 기록 `{"i", "result", "ticks", "log": [], "duels": [], "start", "end", "morale", "rt": "direct" | "auto", "kills"}` 를 `rec.sections` 에 더한다.
- 그 뒤는 지금 `raid()` 꼬리 그대로다: 조직원 손실 · 간부 부상(`_wound`) · 열기 · 명성 · 차지(`_capture`) · 물러남 · 잡힘.

## 3. 턴 나누기
- `opts = {"fights": {묶음 키: {"<구간>": 구간 결과}}, "ask": "<조직 id>" | "", "auto": [틱으로 풀 묶음 키]}` — 없으면 `{}`(지금과 같다).
- `Turn.run(state, orders, t, opts := {})` · `Turn.phases(…, opts)`: `ctx` 에 `fights` · `ask` · `auto` 를 싣는다. 처리기가 `ctx["need"]` 를 채우면 남은 단계를 돌리지 않고 `{"need": …}` 만 돌려준다(작업 사본은 버린다 — 입력 상태 불변).
- `Combat.run_phase`: 습격 묶음을 지금 차례(구역 id → 조직 id)로 풀다가 `raid()` 가 `need` 를 내면 멈춘다. `raid(…, rng, opts := {})` 는 구간마다 ① 우회로면 건너뜀 ② 받은 결과가 있고 검증을 지나면 적용 ③ 2-2 의 때면 `need` ④ 아니면 틱.
- `Game.step(g, t, orders, opts := {})` · `step_player(g, t, draft, opts := {})`: `need` 면 `g` 를 바꾸지 않고 `{"need": …}` 를 돌려준다. 끝까지 돌면 기록 줄에 **쓴 구간 결과만** `fights` 로 남긴다. `replay` 는 기록 줄의 `fights` 를 넣는다(묻지 않음). `autoplay` · AI 미리 보기(`sim/ai.gd`)는 `opts` 없이 부른다.
- 화면 쪽 되풀이(`ui/app.gd`):
```
_end_week():  r = Game.step_player(_g, _t, _draft, {fights: _fights, ask: 내 조직, auto: _auto})
              need 면 → _on_need(r.need)   아니면 → _fights = {} · _auto = [] · 저장 · 보고
_on_need(n):  이 묶음의 방식(설정 또는 창)  결과만 → _auto 에 키 · _end_week()
              직접 · 자동 보기 → 전투 화면(n) → 끝나면 _fights[n.key][n.i] = 결과 · pending_fights 저장 · _end_week()
              (같은 묶음의 다음 구간이면 전투 화면을 닫지 않고 잇는다 · '건너뛰기'면 그 구간은 봇으로 빨리 감고 묶음 키를 _auto 에)
```
- 왜 한꺼번에 미리 뽑지 않나: 앞 습격의 결과(다친 간부 · 바뀐 주인)가 뒤 습격의 준비를 바꾼다. 다시 돌리는 값은 주 처리 평균 2.2 ms(서버 · `docs/성능.md` 2-1)다.
- 난수: 틱 구간은 지금처럼 묶음마다 `Pcg32(seed, turn, "clash", 키)` 하나를 이어 쓴다. 구간 하나가 받은 결과로 바뀌면 뒤 틱 구간이 쓰는 난수 자리가 달라지지만, 같은 `fights` 면 늘 같다. `fights` 가 비면 지금 해시와 같다(회귀 시험).

### 4-4. 구간 판 `fight/section.gd`
- `make(t, need, opts) -> d` — `opts`: `ctrl`(조종할 간부 id · 없으면 등급 높은 순 첫째) · `fight`(표 `fight.json`). `d = {"world", "mine": [내 쪽 간부], "ctrl", "foes", "bots", "ais", "wait": [아직 못 선 조직원], "morale", "frames", "over", …}`.
- `step(d, human = null)` — 한 프레임. `human` 이 없으면 봇이 조종 간부도 움직인다(자동 플레이). `human["swap"]` 이면 교대.
- `set_ctrl(d, id)` — 조종 간부 고르기(살아 있는 내 간부만) · `party(d)` — 내 간부 목록(위 표시 · 고르기 창).
- 동시에 치는 수 `attackers` 는 **대상마다** 센다(C4-1 — 패턴을 내는 AI 는 대상을 바꾸지 않는다). 내 간부가 여럿이면 한꺼번에 더 많은 적이 친다.
- `outcome(d) -> 구간 결과` — 끝난 뒤(`d["over"] != ""`) 2-3 꼴로. `simulate(t, need, opts, max_frames)` — 그림 없이 끝까지(시험 · 빨리 감기).
- 끝: 지키는 쪽 머릿수 0 또는 사기 0 → `att` · 들어가는 쪽 머릿수 0 또는 사기 0 또는 시간 초과 → `def`.
- 세우기: 간부는 전부, 조직원은 쪽마다 `on_field` 명까지 서고 쓰러지면 `wait` 에서 채운다(남은 수 = 서 있는 수 + `wait`).
- 내 쪽 = 조종 · 봇(`fight/bot.gd`)이 움직이는 간부 + 적 AI 프로필로 움직이는 조직원. 상대 쪽 = 간부 · 조직원 모두 적 AI 프로필(`fight/enemy_ai.gd`). 한 대상에 동시에 패턴을 내는 수는 `attackers`.

### 4-5. 사기 · 시간 · 카드 · 카피 (틱과 같은 `combat.json` 값)
- 틱 길이 `tick_sec`(3층) — 시간 상한 = `tick_cap` × `tick_sec` 초. 틱 길이마다: 머릿수가 처음의 절반 밑인 쪽 사기 −`half_tick`.
- 간부가 쓰러지면 그 쪽 −`officer_down`, 적 간부를 쓰러뜨린 쪽 +`duel_win`. 사기 0 인 쪽은 물러난다(조직원이 흩어지고 구간 끝).
- 부상: 간부에게 쓰러짐 `duel.ko_wound` · 조직원에게 쓰러짐 `raid.down_wound`.
- 카드(첫 구간만): `charge` 들어가는 쪽 피해 × `dmg_bp` · `surprise` 처음 `skip_ticks` × `tick_sec` 초 동안 지키는 쪽이 치지 못한다 · `ambush` 처음 `tick_sec` 초 동안 지키는 쪽 피해 × `dmg_bp` · `shield` 그 쪽 조직원이 받는 피해 × `loss_bp`.
- 카피: 같은 방의 간부가 기술을 낼 때마다(**같은 편도** · 보는 사람이 **기절 중이어도** — castle_common 92차 해석 ⑥), 서 있는 다른 `can_copy` 간부의 `seen[기술]` 더하기 값 +1. 기술 id 는 이 판 규칙에 있는 것만(게이지 기술 = 신호의 id · 보스 패턴 기술 = 그 동작의 `skill_id`). 한 신호는 한 번만 센다(배속으로 그림이 비우기 전에 여러 번 불려도).
- 기습 중 지키는 쪽 사람 입력은 치기 · 기술 · 대시를 뺀다(움직이기 · 막기 · 구르기만).
- 92차 해석(`fight/world.gd`): ① 룰렛(`roulette` 을 아는 사람)이 같은 등급 이상의 기술을 같은 피해로 돌려준다 — 즉사 계열이면 친 쪽 체력 1 ② 막아도 한 방 ④ 한 방이 lethal 보다 앞 ⑤ 엇엇박 self_cost 는 체력 1(castle_M3D 그대로).

### 4-6. 결정성 · 난수
- `fight/` 는 Godot `RandomNumberGenerator`(시드 = `need.seed` 에서 가른 값)를 쓴다 — castle_M3D 그대로. **이 판의 '시드는 SHA-256 · Pcg32' 규칙의 예외**다: 실시간 판정의 값은 구간 결과(정수)로 줄어 기록된 뒤에만 상태에 들어가므로 기기마다 실수가 달라도 상태 해시는 같다. 같은 기기 · 같은 시드 · 같은 입력이면 같은 결과(시험 · verify)는 지킨다.

## 7. 저장 v2 · 설정
- `format_version` 2. 기록 줄 `{"turn", "orders", "fights": {묶음 키: {"<구간>": 구간 결과}}}` · 맨 위 `"pending_fights": {…}`(이번 주에 이미 끝낸 구간 — `pending` 과 짝).
- 옮기기 `_v1_to_v2`: 모든 기록 줄에 `"fights": {}` · 맨 위 `"pending_fights": {}`.
- 불러올 때: 구간 결과의 꼴이 틀리면 그 결과를 버리고 알린다(`notes`). 버린 결과가 기록 줄의 것이면 저장된 상태와 다시 돌린 상태가 달라질 수 있으므로 상태를 믿고 이어 한다(지금 `rebuild_reports` 의 `same` 이 거짓이 되는 길 그대로).
- 정수만: 구간 결과는 `State.ints` 를 지난다(실수 없음).
- 설정 `user://settings.json` `{"format": "castle_strategy.settings", "v": 1, "fight_mode": "ask" | "direct" | "auto" | "result"}` — 깨졌으면 기본값.
